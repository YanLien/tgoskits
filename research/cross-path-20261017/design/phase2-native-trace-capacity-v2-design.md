# 严格相位追踪容量修订设计

本修订只准备新的测量候选，处理[严格真板AB1失败](../results/strict-native-phase-v1-AB1-failure-audit-v1.md)暴露的CPU3容量不足。原失败、原源码及工件保持不变；捕获工具采用[离线修订](../results/strict-native-fit-capture-repair-v1.md)的完整使用链方案，并须先完成其Spec→Quality。用户已要求继续推进主线，本设计不要求重复授权，也不进行Git写入。

## 1. 容量与实验身份

`diagnostics.rs::record_at()`在CPU缓冲区不存在或预留序号超过容量时增加全局`DROPPED`。原AB1的CPU3保留16,384条，达到`CAPACITY`；总保留22,343条、dropped=19,839。已知存在容量耗尽，但缺少逐原因计数，不能把全部丢样唯一归因为CPU3，也不能据此解释干扰传播。

### 1.1 最小选择

采用统一扩大现有预分配缓冲区：`CAPACITY`由16,384改为65,536，附英文注释说明这是测量容量及需要重新配对开销。`initialize()`仍在Guest启动前分配，`record_at()`、原子序、IRQ守卫、`finish()`、事件种类及导出规则均保持原字节。一个`Slot`含五个`AtomicU64`；按AArch64的40B槽估算，四CPU槽存储从2.5MiB增至10MiB，不包含Vec及冻结副本。完整实际内存和丢样仍由新运行判断。

缩短窗口或降低A/B压力会同时改变研究输入；采样或过滤事件会改变阶段关联分母。二者不用于本次修订。65,536是有余量的有界容量选择，不保证任意负载零丢样；再次失败就保留事实并停止余项，不自动继续增大或延长时间。

### 1.2 兼容与回滚

在新的普通源码副本中，仅变更702份正式捕获源中的`virtualization/axvm/src/diagnostics.rs`这一份。其余701份必须逐项与原正常702一致。完整普通树另建manifest，原702清单及tar作为父身份保留，新702清单另有SHA；不能继续称新版本等于原702 SHA。既有工具的`normal702_sha256`字段可保留兼容名称，但它必须绑定新的702成员清单，报告明确父子身份。

压力A/B、32任务/策略、20ms周期、10ms截止期、250µs/4ms生产相位界、390B init、批准worker、GCC、kernel/base、亲和性和900/920秒预算不变。保留旧候选即可回滚；新候选不应用主工作树，不修改平台、IRQ、定时器或设备语义。容量改变不能据旧版开销直接校正新数据。

## 2. 新候选与验证门

复用已经审阅的`native_once.py`所有权、真实wait、单次启动、主96交付及前项成功门，不建立另一套长期控制器。新的原始输出根为`raw/strict-native-phase-v2/`，旧AB1额度已耗尽且原后项停止不变；新版本每项另有明确一次性额度，离线准备不消耗硬件额度。

### 2.1 离线边界

先准备源码、独占target/缓存及工具的普通副本，重新冻结准确输入。`capture_native.py`以已双审版本为基准，不改完整tail gates；`native_once.py`仅调整新输出根及必要路径输入。不存在的外部输入、额外源码或非批准缓存都继续拒绝。运行`cargo fmt -p axvm`及`cargo xtask clippy --package axvm`，保存实际命令与退出；如格式化带出无关差异则恢复无关文件并记录。

本次是容量参数变化，不改变缓冲区算法。复用真实完整功能门证明零丢样、全事件导出、双策略任务和退休，不新增“常量等于65,536”的测试或复制录制器模型。已有AB1是真实容量失败证据；新候选未运行前不称其修复成功。任何新增工具行为仍须按既有通用合同证明缺陷敏感度，不能把旧工具的批准直接转给改动后的字节。

### 2.2 真板及研究边界

离线候选经Spec→Quality和Root独立复制检查后，另核当前宿主所有权、服务可用性和准确启动输入。新版本按AB1、AB0、0顺序逐项最多一次，任何失败、捕获不完整或本次释放未知均停余项；每项正常全功能审计和双审通过才进入下一项。保留旧运行release=unknown，当前服务可用性只作为新申请条件，不回填旧释放。

板卡与外层分别仍为900/920秒，cleanup10秒、capture30秒，单项工件捕获上限512MiB。输出Trace增多可能触及串口或总预算，超时如实失败，不放宽成功匹配或时间。原丢样时导出前拒绝的规则保持，若仍失败必须写清实际保留计数与真实导出事件数。

本次离线准备不执行板卡、QEMU、相位性能分析或开销队列。正常真板功能及legacy生命周期证据全部完成后，才能实现完整相位分析、做本版本匹配的追踪开/关和随机重复四组。M2、Joint、阶段0～2及goal整体保持未完成。
