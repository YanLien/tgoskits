# 先行工作核对与对照方案

核对日期：2026-10-17。本文承接仓库根目录 `论文提要.md` 第 2 方向 B 的基线复现前提。当前文件是研究设计和缺口登记，不是已有方法的性能复现报告；没有把论文中的数值、平台结果或实现能力写成 AxVisor 结果。

## 已登记的对照方法

| 方法 | 论文提要中的对照点 | 在 AxVisor 中必须对齐的变量 | 当前状态 |
|---|---|---|---|
| H-MBR | Hypervisor 层 VM 级内存带宽预留 | PMU 事件/单位、补充周期、预算结算、节流动作、vCPU 迁移、关键 VM 指标 | 未固定源码和硬件，未复现 |
| MemGuard in Bao | Hypervisor 级内存带宽监管 | 计数器归属、采样/溢出开销、带宽单位、节流粒度和 Guest 调度 | 未复现 |
| MemGuard-RW | 读写分账 | 读写事件可用性、计数器数量、预算换算和监管开销 | 未复现 |
| MCTI/SchIM | 关键性与 Deadline 参与隔离决策 | 关键性语义、预算耗尽动作、Deadline 输入、硬件支持依赖 | 未复现；不能当作纯软件基线 |
| vC2M | 多资源联合分配的窗口外基础对照 | CPU/Cache/带宽资源模型、静态/动态配置、切换成本和公平性 | 仅作为文献边界登记，未复现 |

论文和代码来源应在获得固定版本后记录：URL/DOI、源码 commit 或发行包哈希、构建工具链、目标 SoC/内核、许可证和不可复现实验步骤。只有这些字段齐全，方法才可以进入阶段四的“已有方法可比基线”组。

## 统一可比实验协议

方向 B 只有在真板能力门禁通过后才执行。每个方法至少需要同一块板卡、同一固件/DTB、同一 Guest 镜像、同一 vCPU 亲和性、同一 CPU 频率策略、同一干扰工作集和同一计数器单位。必须分开报告：

1. 监管前后的关键 Guest ISR P95/P99/P99.9/max、Deadline miss ratio；
2. PMU 计数与 VM/vCPU 运行区间的归属误差；
3. 定时补充、PMU 溢出和实际节流各自的时间/CPU 开销；
4. 普通 VM 吞吐、公平性和监控中断干扰；
5. vCPU 共享、迁移和停止/恢复时的预算结算状态。

`ack_observed_ns` 只能作为独立 Host 观察窗口；Guest ISR 分布必须使用校准后的 Guest 时间戳。最大观测值不写成 WCET/WCRT。

## 进入阶段四的门槛

- `research/rt-virtualization-20261017/configs/true-board-run-template.json` 的 `capability_gate` 全部由真实板卡证据填写，且 `hardware_claim_allowed` 仍由验收结果决定；
- 先完成 AxVisor `off` 匹配基线，再完成单项机制和监控开销；
- 只有计数器归属、预算结算和节流动作可以在相同单位下重现，才把 H-MBR/MemGuard 类方法列入可比组；
- 若硬件事件或软件许可证无法对齐，保留为“相关工作边界”，不得给出数值优劣结论；
- 方向 B 未满足以上门槛前，不实现 VM 级带宽预算，也不以 QEMU CPU/Linux 负载夹具代替内存带宽证据。

## 当前结论

当前仓库已有方向 A 的 QEMU 测量链和 A0 原型证据，但没有方向 B 的硬件能力、固定先行实现或可比性能数据。因此方向 B 仍是候选方向，尚未被测量选择，也不应与 A0 联合扩展。

## 公开来源核对（2026-10-17）

以下来源已通过公开页面核对到论文或项目入口，但仍未在 AxVisor 当前主机上构建、部署或复现实验：

- **H-MBR**：Dagstuhl/OASIcs 页面和 arXiv 条目均可访问。论文将其描述为 VM-centric、OS/platform-agnostic 的 hypervisor-level memory bandwidth reservation，并报告受监管负载的开销结果。来源：[Dagstuhl/OASIcs](https://drops.dagstuhl.de/entities/document/10.4230/OASIcs.NG-RES.2025.4)、[arXiv:2502.02437](https://arxiv.org/abs/2502.02437)。尚缺固定源码 commit、目标板 PMU 事件、构建步骤和同配置原始数据。
- **MemGuard-RW**：UFSC 记录和 IEEE 页面可访问；公开摘要明确其使用读/写两个性能计数器并比较双计数器与原始单计数器分析。来源：[UFSC record](https://repositorio.ufsc.br/handle/123456789/267662)、[IEEE entry](https://doi.org/10.1109/ISORC65339.2025.00021)。尚缺可直接重建的 Bao commit、计数器事件映射和与 RK3588 对齐的预算单位。
- **MemGuard**：原始 MemGuard 参考实现入口为 [heechul/memguard](https://github.com/heechul/memguard)；它不是 Bao hypervisor 实现，不能直接作为 AxVisor 的 VM-level 可比基线。Bao 的公开仓库为 [bao-project/bao-hypervisor](https://github.com/bao-project/bao-hypervisor)，其当前公开活动只能作为后续固定版本的入口，不能替代已完成复现。
- **MCTI/SchIM**：Boston University 官方页面确认论文 DOI，并列出 RT-Bench 与 Jailhouse-RT 作为代码/硬件工件入口。来源：[CPSLab MCTI page](https://cpslab.bu.edu/papers/mcti-rtsj-2024)。其硬件支持和任务级语义不能直接改写成 AxVisor 纯软件带宽基线。
- **vC2M**：作者公开 PDF 描述 CPU、cache 和 memory bandwidth 的整体分配以及 Xen 原型。来源：[作者 PDF](https://www.cis.upenn.edu/~linhphan/papers/vC2M-dac19.pdf)。这是窗口外基础对照，不能与当前 QEMU/A0 结果直接合并。

这些来源核对只改变“来源已定位”的状态，不改变表格中的“未复现”状态。进入阶段四前仍需冻结源码/版本、硬件、PMU 事件单位、Guest 工作集、调度/亲和性和原始数据格式。
